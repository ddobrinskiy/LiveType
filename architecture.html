Что общее, а что платформенное

Kotlin и Swift здесь не являются одним общим исходным модулем. Переиспользуется поведение и wire-контракт, а системные границы — клавиатура, микрофон, sandbox и подпись — реализованы отдельно для Android и iOS.

Где именно переиспользуется код

Общее между Android и iOS

  • Worker API: /token, /usage, device-secret auth.
  • OpenAI Realtime wire rules: bare WebSocket URL, session update, transcript and usage events.
  • Модель, цены, billing and D1 — только Worker.
  • Локальный protocol double и headless E2E runner.

Уникально для Android

  • Kotlin InputMethodService и собственный keyboard view.
  • AudioRecord для PCM-захвата.
  • SharedPreferences, Android permissions и manifest.
  • Gradle BuildConfig, adb reverse, Android AVD.
  • Composing text, cursor actions, paste and word-delete через InputConnection.

Уникально для iOS

  • SwiftUI host app + UIInputViewController keyboard extension.
  • AVAudioEngine и AVAudioConverter.
  • App Group UserDefaults между host и extension.
  • Full Access, iOS keyboard settings, Xcode signing and entitlements.
  • textDocumentProxy.insertText: нет Android-style composing region.

Главный вывод. Переиспользуется не UI и не системный keyboard code, а договорённость: какие hints отправить Worker, как получить ephemeral token, как открыть Realtime session и как отправить raw usage. Поэтому баг в wire-контракте может затронуть обе платформы, а баг в IME/keyboard sandbox — только одну.
